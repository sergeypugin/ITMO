# Самописный справочник по x86-64 в NASM

## Порядок байт в памяти (Little-Endian)

Архитектура x86-64 использует порядок байтов **Little-Endian** (младший байт по младшему адресу):

* **Числа в памяти:** младшие байты многобайтового числа записываются первыми.
  Например, 64-битное шестнадцатеричное число `0x0102030405060708` в памяти будет лежать как байты:
  `08 07 06 05 04 03 02 01`.
* **Строки в памяти:** Символы строки -- это массив отдельных 1-байтовых элементов, поэтому они располагаются в естественном порядке чтения слева направо: `'h'`, `'e'`, `'l'`, `'l'`, `'o'`, `0x00`.
* **Почему Little-Endian удобен для процессора:**
  1. Операция приведения типа к меньшему (например, из 64-битного числа в 32-битное) не требует изменения адреса: младшие 32 бита лежат по тому же самому начальному адресу в памяти.
  2. Арифметические операции сложения и умножения выполняются начиная с младших разрядов, поэтому процессор может начинать вычисления сразу при чтении первого байта из памяти.

## Регистры общего назначения

Все 16 основных регистров архитектуры x86-64 (`rax`--`rsp`, `r8`--`r15`) являются **полноценными 64-битными (8-байтовыми)** регистрами.

### Таблица регистров

| Регистр (64-бит) | Номер в кодировке (r0--r15) | Историческое имя | Тип сохранения | Роль в соглашении о вызовах (Calling Convention) и применение |
| :--- | :--- | :--- | :--- | :--- |
| `rax` | `r0` | Accumulator | Caller-saved | 1-е возвращаемое значение из функции; номер системного вызова в `syscall`; аккумулятор для арифметики (`mul`/`div`). |
| `rcx` | `r1` | Counter | Caller-saved | 4-й аргумент функции; счетчик для циклов и битовых сдвигов (`cl`). Аппаратно затирается при `syscall`. |
| `rdx` | `r2` | Data | Caller-saved | 3-й аргумент функции и `syscall`; 2-е возвращаемое значение; старшая часть при делении/умножении (`rdx:rax`). |
| `rbx` | `r3` | Base | **Callee**-saved | Базовый регистр общего назначения. Функция обязана сохранить его перед использованием. |
| `rsp` | `r4` | Stack Pointer | **Callee**-saved | Указатель на вершину стека (адрес последнего положенного элемента). |
| `rbp` | `r5` | Base Pointer | **Callee**-saved | Указатель на базу (начало) текущего стекового кадра. |
| `rsi` | `r6` | Source Index | Caller-saved | 2-й аргумент функции и `syscall`; индекс/указатель источника в строковых операциях. |
| `rdi` | `r7` | Destination Index | Caller-saved | 1-й аргумент функции и `syscall`; индекс/указатель назначения в строковых операциях. |
| `r8` | -- | Register 8 | Caller-saved | 5-й аргумент функции и `syscall`; регистр общего назначения. |
| `r9` | -- | Register 9 | Caller-saved | 6-й аргумент функции и `syscall`; регистр общего назначения. |
| `r10` | -- | Register 10 | Caller-saved | 4-й аргумент для `syscall` (заменяет `rcx`); временный регистр общего назначения. |
| `r11` | -- | Register 11 | Caller-saved | Временный регистр; аппаратно затирается при `syscall` (сохраняет флаги `rflags`). |
| `r12`--`r15` | -- | Registers 12--15 | **Callee**-saved | Регистры общего назначения. Идеальны для переменных, которые должны пережить вызовы других функций (`call`). |

### Разрядность и доступ к частям регистров

Каждый 64-битный регистр позволяет адресовать свои младшие части (32, 16, 8 бит):

* Традиционные регистры (`rax`, `rbx`, `rcx`, `rdx`):
  * 64 бита: `rax`
  * 32 бита: `eax` (запись в 32-битную часть автоматически обнуляет старшие 32 бита `rax`)
  * 16 бит: `ax`
  * 8 бит: `al` (биты 0..7), `ah` (биты 8..15)

* Индексные и указательные регистры (`rsi`, `rdi`, `rbp`, `rsp`):
  * 64 бита: `rsi`, `rdi`, `rbp`, `rsp`
  * 32 бита: `esi`, `edi`, `ebp`, `esp`
  * 16 бит: `si`, `di`, `bp`, `sp`
  * 8 бит: `sil`, `dil`, `bpl`, `spl`

* Дополнительные регистры (`r8`--`r15`):
  * 64 бита: `r8`, `r9`, `r10`, `r11`, `r12`, `r13`, `r14`, `r15`
  * 32 бита: `r8d`, `r9d`, `r10d`, `r11d`, `r12d`, `r13d`, `r14d`, `r15d`
  * 16 бит: `r8w`, `r9w`, `r10w`, `r11w`, `r12w`, `r13w`, `r14w`, `r15w`
  * 8 бит: `r8b`, `r9b`, `r10b`, `r11b`, `r12b`, `r13b`, `r14b`, `r15b`

## Синтаксис адресации памяти и команда LEA

### Квадратные скобки `[...]` (Разыменование адреса)

В NASM квадратные скобки означают **обращение к ячейке памяти** по указанному адресу (аналог разыменования указателя `*ptr` в C):

* `mov rax, rbx` -- скопировать само 64-битное значение из регистра `rbx` в `rax`.
* `mov rax, [rbx]` -- прочитать 8 байт из оперативной памяти по адресу, который записан в `rbx`, и положить их в `rax`.
* `mov byte [rdi], 0` -- записать 1 байт со значением `0` в память по адресу `rdi`.

Общий вид адресации в x86-64: `[base + index * scale + displacement]`, где:
* `base` -- базовый регистр адреса (например, `rdi`).
* `index` -- индексный регистр смещения (например, `rcx`).
* `scale` -- множитель масштаба (`1`, `2`, `4` или `8`).
* `displacement` -- постоянное числовое смещение (константа).

### Команда `lea` (Load Effective Address)

Команда `lea dst, [выражение]` вычисляет адрес внутри квадратных скобок **без обращения к памяти** и записывает результат вычисления в `dst`.

* `mov rax, [rbx + 8]` -- идет в оперативную память по адресу `rbx + 8` и читает оттуда данные.
* `lea rax, [rbx + 8]` -- не идет в память, а просто складывает значение `rbx` с числом `8` и записывает результат в `rax` (эквивалентно `rax = rbx + 8`).

Преимущества `lea`:
1. Позволяет выполнить сложение, умножение на 1/2/4/8 и добавление смещения за одну инструкцию: например, `lea rdx, [rax + rcx*4 + 10]`.
2. В отличие от команды `add`, инструкция `lea` не изменяет флаги процессора (`rflags`).

## Функции, Системные вызовы (Syscalls) и Соглашение о вызовах

### Разница между вызовом функции и системным вызовом

| Параметр | Вызов пользовательской функции (`call foo`) | Системный вызов к ядру ОС (`syscall`) |
| :--- | :--- | :--- |
| Номер / Адрес | Адрес функции передается в `call` | Номер системного вызова кладется в `rax` |
| 1-й аргумент | `rdi` | `rdi` |
| 2-й аргумент | `rsi` | `rsi` |
| 3-й аргумент | `rdx` | `rdx` |
| 4-й аргумент | `rcx` | `r10` (так как `syscall` затирает `rcx`) |
| 5-й аргумент | `r8` | `r8` |
| 6-й аргумент | `r9` | `r9` |
| 7+ аргументы | Передаются через стек | Системные вызовы Linux принимают не более 6 аргументов |
| Затираемые регистры | Caller-saved регистры | `rax` (результат), `rcx` (старый RIP), `r11` (старые флаги) |

### Передача более 6 аргументов в функцию

Если функции требуется передать более 6 аргументов, программист вызывающего кода (**Caller**) должен вручную положить лишние аргументы на стек перед вызовом и очистить стек после него:

```asm
; Пример вызова функции foo(10, 20, 30, 40, 50, 60, 70, 80)
; 1..6 аргументы идут в регистры, 7 и 8 идут в стек:

push 80         ; Вызывающий кладет 8-й аргумент на стек
push 70         ; Вызывающий кладет 7-й аргумент на стек (он окажется на вершине)
mov r9, 60      ; 6-й аргумент
mov r8, 50      ; 5-й аргумент
mov rcx, 40     ; 4-й аргумент
mov rdx, 30     ; 3-й аргумент
mov rsi, 20     ; 2-й аргумент
mov rdi, 10     ; 1-й аргумент

call foo        ; Инструкция call кладет адрес возврата на стек и переходит в foo

add rsp, 16     ; Вызывающий вручную освобождает 16 байт стека (2 аргумента по 8 байт)
```

## Основные команды x86-64

### Пересылка данных
* `mov dst, src` -- копирование данных из `src` в `dst`.
* `movzx dst, src` -- копирование с заполнением старших бит нулями (Move with Zero-Extend).
* `lea dst, [src]` -- загрузка эффективного адреса (вычисление без обращения к памяти).
* `push src` -- уменьшить `rsp` на 8 и записать `src` по адресу `[rsp]`.
* `pop dst` -- прочитать значение из `[rsp]` в `dst` и увеличить `rsp` на 8.

### Арифметика и логика
* `add dst, src` / `sub dst, src` -- сложение / вычитание.
* `inc dst` / `dec dst` -- увеличение / уменьшение на 1.
* `imul dst, src` -- знаковое умножение.
* `mul src` -- беззнаковое умножение `rax` на `src`, результат в паре `rdx:rax`.
* `div src` -- беззнаковое деление 128-битного `rdx:rax` на `src`. Частное кладется в `rax`, остаток -- в `rdx`. Перед вызовом `div` необходимо обнулить `rdx` (`xor rdx, rdx`).
* `neg dst` -- смена знака числа (дополнительный код: `dst = -dst`).
* `and`, `or`, `xor`, `not` -- побитовые логические операции.

### Сравнение и переходы
* `cmp op1, op2` -- невидимое вычитание `op1 - op2` для установки флагов `ZF`, `CF`, `SF`, `OF`.
* `test op1, op2` -- невидимое побитовое `op1 AND op2` для установки флагов (быстрая проверка на ноль: `test rax, rax`).
* `jmp label` -- безусловный переход.
* `je` / `jz` -- переход, если равно / ноль (`ZF = 1`).
* `jne` / `jnz` -- переход, если не равно / не ноль (`ZF = 0`).
* `ja` / `jb` -- переход, если больше / меньше (для беззнаковых чисел).
* `jae` / `jbe` -- переход, если больше или равно / меньше или равно (беззнаковые).
* `jg` / `jl` -- переход, если больше / меньше (для знаковых чисел).
* `jge` / `jle` -- переход, если больше или равно / меньше или равно (знаковые).
* `js` / `jns` -- переход, если отрицательное / неотрицательное.

### Управление выполнением
* `call label` -- положить адрес следующей инструкции на стек и перейти к `label`.
* `ret` -- снять адрес со стека и передать туда управление.
* `syscall` -- переключение в ядро операционной системы.
