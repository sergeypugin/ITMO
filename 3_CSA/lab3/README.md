# Лабораторная №3

Вам предстоит изучить различные архитектуры компьютера, написав несколько программ на разных ассемблерах.

Вся документация по ним назодится во [wrench](https://github.com/ryukzak/wrench).

В этом репозитории есть лабораторная № 3:
- На версии `0.0.5.0 (2d79e30)`:
  - [acc32](lab3/acc32/README.md)
  - [f32a](lab3/f32a/README.md)
  - [risc-iv](lab3/risc-iv/README.md)
- На версии `0.0.6.1 (06ffe0c)`:
  - [m68k](lab3/m68k/README.md)

> [!note]
> С вероятностью 100% вам понадобится знать, что в ASCII-коде `\n` -- это 10 (LF).
>
> [Таблица ASCII](https://www.industrialnets.ru/files/misc/ascii.pdf) | [Перевод строки в ASCII-коды](ascii_codes.py)

> [!tip]
> Для форматирования во время работы с лабой 3 рекомендую скачать из [релизов ***wrench***](https://github.com/ryukzak/wrench/releases) для вашей ОС. Там при распаковке будет лежать очень полезный файл `wrench-fmt.exe`, документация по которому откроется после ввода в терминале следующей команды:
> ```bash
> path_to_exe/wrench-fmt --help
> ```
>
> Также для того, чтобы получать отчёт без загрузки на сайт (локально, поделиться ссылкой не получится), воспользуйтесь файлом `wrench.exe`, документацию по которому можно увидеть после ввода в терминале следующей команды:
> ```bash
> path_to_exe/wrench --help
> ```
> Могу также порекомендовать свою архитектуру файлов и [settings.json](lab3/.zed/settings.json) + [tasks.json](lab3/.zed/tasks.json), чтобы запускать в Zed сразу таску, подходящую для любых архитектур, а не постоянно возиться с флагами ***wrench***

> [!warning]
> При локальном тестировании обратите внимание: для всех отчётов установлены одни и те же лимиты на число команд и объём памяти -- 2000 команд и 1 Кб. Так что пишите в `*.yaml` всегда `limit: 2000` и затем `memory_size: 0x1000` либо меньшие значения в формате dec или hex.

> [!tip]
> У меня было разок или даже два, когда в `Python`-алгоритме выводилось одно, а во ***wrench*** -- совершенно другое. Очень советую сначала закинуть во ***wrench*** просто какую-нибудь программку на 1-2 строки и увидеть 1 упавший тест, который сайт обязан показать.
>
> Так вы узнаете точно, какой именно вывод ожидает программа, и не будете делать две похожие внешне, но при этом совершенно разные внутри программы 🫠
