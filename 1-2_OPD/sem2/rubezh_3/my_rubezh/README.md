## Текст задания:

```
Задание №1. Разработать программу для работы с элементами массива M, в которой:  
1. Массив имеет следующие характеристики:  
- адрес начала массива в памяти БЭВМ - 0x6cc;  
- число измерений исходного массива - 1;  
- количество элементов исходного массива - 21;  
- каждый элемент является знаковым числом с разрядностью 19 бит;  
- нумерация элементов начинается с 3;  
- элементы хранятся в массиве по границам слов, нет необходимости в плотной упаковке;  
2. Для элементов массива необходимо вычислить одно значение по правилам:  
- агрегировать необходимо только для элементы массива с кратными 2-м i-индексами;  
- из выбранных элементов необходимо вычислить исключающее 'ИЛИ' значений и записать результат в память по адресу 0x400.  
- Результатом является одно 32-х разрядное число!  
Примечание: все числа представлены в десятичной системе счисления, если явно не указано иное.
```

## Описание логики программы

Пусть `LEN` - длина массива,
`PTR` - указатель на 1-й элемент массива
`NEW_PTR` - указатель на память для сохранения XOR всех необходимых элементов
`CURID`, `CURH`, `CURL` - индекс (изначально 3), старшее и младшее слово текущего элемента массива
`XORH`, `XORL` - старшее и младшее слово накапливаемого результата (изначально 0)

Отметим, что поскольку числа являются знаковыми и 19-битными, требуется расширение знака старшего слова. 

``` РУССКИЙ
Программа в цикле выполняет LEN итераций:
	Если CURID чётный:	
		Расширяем знак у старшего слова
		Делаем XOR CURH с XORH и CURL с XORL  
	Инкрементируем CURID
	Если не перебрали все элементы:
		Конец итерации, переход к новой
	Иначе:
		Сохранение результатов XORH и XORL по NEW_PTR
		Остановка цикла
```

### Ошибки
#### Ошибка №1: NOT -> NEG

```diff
XORINGH:
    LD CURH
    OR XORH
    ST TMP
    LD CURH
    AND XORH
-   NEG
+   NOT
    AND TMP
    ST XORH
```

#### Ошибка №2: неверная маска для знака отрицательных чисел

```diff
    ;DATA
    ...
    BITM: WORD 0x0004; причём маска для старшего слова
	POSM: WORD 0x0003
-   NEGM: WORD 0xFFFA
+   NEGM: WORD 0xFFFC
```

### Космечические изменения

#### Изменение №1: освобождения места под вектора прерываний

Поскольку [в моём гайде по 3-й рубежной контрольной](..//README.md###Замечание) мы уже узнали, что программа будет грузиться с `0x10` при отсутствии `0RG 0`, то желательно убрать `ORG 0` для того, чтобы осталось место для векторов прерываний и чтобы программа не была привязана к какому-то адресу.  

```diff
- ORG 0
  START:
  ...
```

#### Изменение №2: 16СС -> 10СС

Для читаемости программы были переведены числа из 16СС в 10СС, но только те, что изначально были в 10СС.
Заметим, что `CURID` был равен $11_{16}=17_{10}$ , что могло бы сломать программу, однако $11 \equiv 3 \pmod 2$, так что логика с чётностью не была нарушена

```diff
- CURL: WORD 0x0
- CURH: WORD 0x0
- XORL: WORD 0x0; изначально ставим ноль, с 1-м числом ксор даст само число
- XORH: WORD 0x0
- TMP: WORD 0x0
- CURID: WORD 0x11;3
+ CURL: WORD 0
+ CURH: WORD 0
+ XORL: WORD 0; изначально ставим ноль, с 1-м числом ксор даст само число
+ XORH: WORD 0
+ TMP: WORD 0
+ CURID: WORD 3
```
