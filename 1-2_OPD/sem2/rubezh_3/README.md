## Теория к рубежу

### Основные сокращения, знания которых помогают понять, что происходит:
* `PTR` - PoinTeR - указатель на массив или что-то ещё
* `CURH`, `CURL` - CURrent High, CURrent Low - старшее и младшее слово какой-то временной переменной

### Адресация 

Значит, существует несколько видов работы с памятью (та самая, что зовётся "виды адресации"), но нам понадобятся только эти (не обязательно знать их название, главное уметь использовать):
1. Прямая загрузка: `LD #4`, `ADD #10` - работа с числом после символа '#'. 
	**Важно**: `ADD #10` прибавит к `AC` не двойку в десятичной, а именно десятку, т.к. БЭВМ по умолчанию работает с десятичными числами
2. Прямая относительная: `ADD X`, `OR Y` - работа с числом, что лежит в ячейке с меткой аргумента.
	**Важно**: работает только, когда до ячейки прыгать не более чем 128 ячеек
3. Косвенная: `LD (PTR)` - работа с ячейкой, что находится по адресу `PTR` (отсюда и сокращение в последующих моих работах - pointer)
4. Адресация со смещением по стеку: `LD &1`, `ADD &2` - работа не только с вершиной, но и с другими элементами стека по порядковому номеру относительно вершины. Вершина - 0-позиция, под ней 1-ая позиция и т.д.
	**Важно**: если вдруг Вы просчитаетесь с номером и возьмёте без спросу адрес возврата при вызове подпрограммы, логика полетит и скорее всего Вы пролетите даже `HLT`. Особенно часты ошибки, когда в подпрограмме есть другая подпрограмма.

***
 ***Замечение***:
 Прямая относительная (`LD X`) и адресация со смещением по стеку(`LD &1`) предназначены для одного и того же - работать с памятью по ячейке, которую уже куда-то сохранили. Вторая куда лучше тем, что в ней нет ограничения по отдалённости ячейки, из-за чего используется в серьёзных программах куда чаще. Однако связи с тем, что стек у нас ездит во все стороны и используется для подпрограмм, а метки переменных остаются всегда, советую избегать эти смещения и пользоваться прямой относительной адресацией.
***
**Очень полезная вещь**:
Ещё не забыли, что значит `LD (PTR)`?) Если забыли, см. выше.
Можно использовать `(PTR)+` и `-(PTR)`, т.е. в 1-м случае после обращения к памяти по адресу `PTR` и взятия нужного аргумента `PTR` будет инкрементироваться (+1),
а во 2-м случае до обращения к памяти - декрементироваться (-1).
Такие возможности ассемблера позволяют осуществлять удобный перебор массивов, что, скорее всего, Вы использовали/будете использовать в лабах.
Ещё один наиудобнейший момент: если у Вас есть какой-то счётчик/индекс `CURID`, то вместо
```
LD CURID
INC
ST CURID
```
Вы имеете право сделать лишь
```
LD (CURID)+
```
, что позволит инкрементировать счётчик лишь одной командой!
Однако будьте готовы к тому, что Вы потеряете предыдущее содержимое `AC`, записав в него счётчик (который ещё не инкрементировался). Тоже очень удобная фича для работы с массивами, да и в принципе с циклами. Уверен, к этой рубежке это Вы освоили)

### Команды ветвления

Что касается сравнений чисел, то важно знать команды ветвлениия:

| Команда | Расшифровка                | Условие перехода | Когда применять                                                           |
| :------ | :------------------------- | :--------------- | :------------------------------------------------------------------------ |
| `BR`    | Branch                     | Без условий      | Безусловный короткий переход в пределах $\pm 128$ слов                    |
| `BEQ`   | Branch if Equal            | `Z == 1`         | При равенстве чисел (после `CMP`) или обнулении счетчика                  |
| `BNE`   | Branch if Not Equal        | `Z == 0`         | При неравенстве чисел или ненулевом результате                            |
| `BMI`   | Branch if Minus            | `N == 1`         | Если результат операции отрицательный (знаковый)                          |
| `BPL`   | Branch if Plus             | `N == 0`         | Если результат операции положительный или равен нулю                      |
| `BLT`   | Branch if Less Than        | `N ⊕ V == 1`     | **Для знаковых чисел**: переход, если "меньше" (защищает от переполнения) |
| `BGE`   | Branch if Greater or Equal | `N ⊕ V == 0`     | **Для знаковых чисел**: переход, если "больше или равно"                  |
| `BLO`   | Branch if Lower            | `C == 0`         | **Для беззнаковых чисел** (например, младших слов): переход, если "ниже"  |
| `BHIS`  | Branch if HIgher or Same   | `C == 1`         | **Для беззнаковых чисел**: переход, если "выше или равно"                 |
| `BVS`   | Branch if Overflow Set     | `V == 1`         | Если произошло знаковое переполнение                                      |
| `BVC`   | Branch if Overflow Clear   | `V == 0`         | Если знакового переполнения не было                                       |

***
***Замечание***:
Когда мы говорим "переход, если >" или что-то типо того, то имеется в виду, что в `AC` было `A`, затем мы вычли `B`, а дальше при помощи `NZVC` мы определяем, что да как. Там есть конечно логика, но ну её, как будто её кто-то будет спрашивать

### Тесты

Вам понадобится сделать тесты (по крайней мере после рубежки точно), ибо как Вы будете уверены в том, что программа работает?

**MUST HAVE**: числа 0, 1, -1, 2 (просто проверить ручками, что функция правильно сработает), максимум и минимум в вашей разрядной сетке. 
***
**Важно**: вместо того, чтобы переводить 2 из 10-чной в 16-ричную, можно просто писать `WORD 2`, а не `WORD 0x10` (т.к. по умолчанию в БЭВМ работает с 10-чными числами, уже писал в начале).
***
Остальное - уже на ваше усмотрение. Ну и не забывайте пользоваться калькулятором для вычисления значений функций, он очень удобен, особенно учитывая то, что Вы можете в нём вводить сначала шестнадцатеричные, а затем переключаться на десятичные)

Вычисление $5_{10} \times 10_{16} = 50_{16} = 80_{10}$:

![[VID_20260523_223033_796.gif|304]]

С проверкой отрицательных чисел бывает тяжело, так что воспользуйтесь режимом QWORD в калькуляторе (тыкайте до упора, когда дойдёте до него, будет работа с 32-битными числами, а сверху уже появится "DWORD" для работы с 16-битными) и тыкните кнопку "+/-".

![[VID_20260523_223549_658.gif|340]]


Также для тестов удобно делать `ARR: WORD 10 DUP (0)`, чтобы заполнять оставшийся массив нулями.
**НО!** Использовать следует максимум 4-5 тестовых и обрубать длину-счёткик для `LOOP` на момент тестирования! Иначе состаритесь в ожидании результата (в среднем для каждого вида программ уходит минуты 3-4 лишь на тесты массива длины 4-5)

И также убедительная просьба не забывать писать `ORG 0xABC`, иначе ваши данные будут не по тому адресу, который ожидается программой и был дан по заданию.

Пример теста для массива длины 13 (хотя в проге нужно изменить длину, чтобы не состариться):

``` ASSEMBLY
;TEST DATA:
ORG 0x6df
WORD 10
WORD 1
WORD 0x7FFF;
WORD 0x5FFF;
WORD 8 DUP (0); пусть мусор из тех ячеек массива очистится
```

#### Тип 1А: «Халявный» массив функций
*   **Особенность:** Исходные элементы $\le 16$ бит (читаем по 1 слову). Результат функции гарантированно $\le 32767$. **Математику делаем в 16 битах, а знак расширяем до 32 бит только в конце перед записью.**

#### Тип 1B: «Честный» массив функций
*   **Особенность:** Исходные элементы $\le 16$ бит (читаем по 1 слову). Но результат функции $> 32767$ и переполняет 16-битную сетку. **Требуются 32-битные сдвиги (`ASL/ROL`) и сложения (`ADD/ADC`) со старта.**
*   **Задачи:** **11, 14, 23** (Всего: 3 задачи).

#### Тип 2А: Сумма (SUM) в 32 битах
*   **Особенность:** Исходные элементы $> 16$ бит (читаем по 2 слова). Сложение (`ADD` + `ADC`) 32-битных чисел. Результат — одно 32-битное число.
*   **Задачи:** **5, 10, 18 (21 — дубликат)** (Всего: 4 задачи).

#### Тип 2B: Поиск экстремума (MIN / MAX) в 32 битах
*   **Особенность:** Исходные элементы $> 16$ бит (читаем по 2 слова). Знаковое сравнение 32-битных чисел (по старшему, затем по младшему слову). Результат — одно 32-битное число.
*   **Задачи:** **1, 13, 15, 17 (20 — дубликат)** (Всего: 5 задач).

#### Тип 2C: Логика (AND / XOR) в 32 битах
*   **Особенность:** Исходные элементы $> 16$ бит (читаем по 2 слова). Логические операции на уровне 32 бит. Особый ад в виде XOR без команды XOR. Результат — одно 32-битное число.
*   **Задачи:** **3, 6, 12, 16 (19 — дубликат)** (Всего: 5 задач).
